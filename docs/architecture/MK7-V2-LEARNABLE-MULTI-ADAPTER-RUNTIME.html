1. Architectural Doctrine

Enterprise-first intelligence: controlled at the top, adaptive at the bottom.
ذكاء مؤسسي أولًا: تحكم في الأعلى، وتكيّف في الأسفل.

The MK7 design deliberately separates explicit business routing from latent learned specialization. Business domains remain auditable and controllable, while adapter selection becomes learnable where it adds measurable value.

2. What MK7 v2 Is

Frozen Base Model

Gemma-family model selected according to the hardware envelope. The base weights are not updated during RouterLab training.

يتم اختيار حجم Gemma وفق قيود الهاردوير، وتظل أوزان النموذج الأساسي مجمّدة أثناء تدريب الراوتر.

Frozen LoRA Experts

Examples: ERP, Arabic, Tool, Format, Customer/tenant adapters. Each adapter is independently versioned and evaluated.

محولات متخصصة وقابلة للتدقيق والإصدار المستقل.

Trainable Router

A tiny neural network consumes a prompt representation and produces routing scores over Base/No-Adapter and available LoRA experts.

شبكة صغيرة جدًا هي الجزء الأساسي القابل للتدريب في v2.

Production Sparsity

Soft routing may be used for training and analysis; serving should evaluate Top-1/Top-2 execution to avoid unnecessary adapter compute.

في الإنتاج نهدف لتشغيل أقل عدد ممكن من المحولات اللازمة.

5. Simplified Forward Model

routing_weights = softmax(router(prompt_representation))

y = W_base(x)
for adapter_i in selected_adapters:
    y += routing_weights[i] * LoRA_i(x)

# Training: soft candidate routing
# Inference: prune to Top-1 / Top-2 before adapter delta compute
Important: routing coefficients are learned numerical weights. They are not literal percentages of knowledge or intelligence.

6. Training Strategy

Frozen

Base model weights

All candidate LoRA experts

Trainable

Router parameters only in RouterLab-001

Objective

Task loss + routing/balance regularization only when justified by observed collapse or imbalance.

Entropy regularization must not blindly force uniform routing per request. Batch-level utilization and task quality are more important than making every prompt distribute evenly.

7. Dataset Factory

Negative / trapPrevent collapse and over-routingNon-ERP prompts containing ERP-like words; irrelevant language cues
Adversarial routingMeasure robustnessAmbiguous, mixed-intent, long prompts

The dataset should not hard-code arbitrary values such as “ERP = 0.7, Tool = 0.3” unless they are used for a dedicated supervised-routing experiment. Primary supervision should remain task quality, with route labels used as a weak or auxiliary signal where appropriate.

8. RouterLab-001 Benchmark

Primary KPI: Oracle Gap
Oracle Gap = Oracle adapter performance − Learned Router performance.
BaselineWhy it exists
Base onlyGeneral capability floor
Oracle adapterUpper bound when the correct adapter is known manually
Wrong adapterMeasures routing sensitivity and specialist interference

MK7 learned soft routerMeasures dynamic mixture quality
MK7 Top-1 / Top-2Measures production-quality sparsity trade-off

Release criterion: v2 is not justified if the learned router does not close most of the Oracle Gap or cannot outperform simpler static routing/composition on mixed-domain tasks.

Top-K saves adapter compute only if pruning happens before unselected adapter deltas are evaluated. Top-K alone does not automatically save VRAM when all adapters are already resident on the GPU; memory savings require registry/cache/load policy.

10. Version Roadmap

MK7 v1

Explicit/Semantic multi-adapter routing. Auditable and controllable.

MK7 v1.5

Adapter registry, hot-swap/cache, Top-K hard routing, production benchmarks.

MK7 v2

Learnable Mixture-of-Adapters. Frozen experts, learned prompt router.

MK7 v3

Native small MoE underneath explicit MK7 business routing.

11. Non-Goals for v2.0

  • No pretraining of a new foundation model from scratch.
  • No token-wise or layer-wise router in the first production prototype.
  • No assumption that weighted LoRA coefficients equal semantic percentages.
  • No forced adapter merging when dynamic routing is the source of specialization.
  • No claim of production readiness until latency, VRAM, Oracle Gap, collapse, and regression tests pass.

12. Final Principle

Do not make all knowledge, all computation, and all tools run for every request. Route aggressively at every layer where routing produces measurable value.
لا تشغّل كل المعرفة وكل الحساب وكل الأدوات لكل طلب؛ وجّه الذكاء بقوة في كل طبقة عندما يثبت القياس أن التوجيه يضيف قيمة.
