The methodology

We avoided a single opaque training command. Every stage had an exit condition and preserved evidence.

Lock the identitySeparate standard Gemma 3 270M IT from FunctionGemma, ByT5, and legacy models.
Verify the environmentUse one fixed Python 3.11 environment with PyTorch CUDA, PEFT, TRL, and exact paths.
Validate the dataset100 records split 64/16/20, no duplicate inputs, no split overlap, valid UTF-8 and JSONL.
Run a one-step preflightForward, backward, optimizer step, adapter save, process restart, adapter reload, inference.
Prove learnabilityMicro-overfit eight examples before scaling. The model reached 8/8 with valid JSON.
Run controlled LoRATrain with validation, early stopping, preserved checkpoints, and fresh-process evaluation.
Audit the evaluatorWhen metrics contradicted raw behavior, inspect generated text and token boundaries instead of retraining blindly.

The apparent failure

The first evaluator reported 0% validation and 0% test accuracy. We did not accept that result because:

  • the eight-example micro-overfit had already reached 100%;
  • training loss had fallen near zero;
  • the adapter reloaded correctly in a fresh process;
  • all generated outputs were non-empty.

Raw generations began with the correct JSON, then repeated it with <end_of_turn> until the generation limit. The old parser captured from the first opening brace to the last closing brace and combined multiple JSON objects into invalid JSON.

{"intent":"employee.create"}<end_of_turn>
{"intent":"employee.create"}<end_of_turn> ...

One isolated fix: stop at the first <end_of_turn> or extract the first balanced JSON object. No retraining, data modification, or decoding change was used for rescoring.
